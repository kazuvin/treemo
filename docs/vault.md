# 保管庫と iCloud

メモの置き場所、読み書きの手順、iCloud Drive での同期に伴う注意点。
要件は [要件定義](requirements.md) の VAULT にある。

## 方針

- **同期はアプリで作らない。** 保管庫は iCloud Drive 上のただのフォルダで、同期は
  iCloud に任せる。Obsidian と同じ考え方。
- **保管庫にはメモしか置かない。** アプリの状態（最後に開いた保管庫、折りたたみの状態、
  最近開いたメモ、索引のキャッシュ）は保管庫の外、
  `~/Library/Application Support/me.kazuvin.treemo/` に置く。
  - 1 つのファイルに状態をまとめた DB（SQLite など）を iCloud に置くと、同期の途中で
    壊れやすい。
  - 端末ごとに違ってよい情報を同期すると、端末どうしで上書きし合う。
- MVP では、保管庫の中にアプリ用のフォルダ（Obsidian の `.obsidian/` に当たるもの）を
  作らない。保管庫ごとの設定が要るようになったら `.treemo/` を検討する。

## 保管庫を選ぶ

- 初回はフォルダ選択ダイアログを開き、最初の候補に iCloud Drive
  （`~/Library/Mobile Documents/com~apple~CloudDocs/`）を示す。
- 選んだパスはアプリの状態として覚え、次回はそれを開く。見つからなければ選び直させる。

## 読み書きの窓口

ファイルシステムには Rust 側のコマンドからしか触らない。WebView から
`tauri-plugin-fs` で直接触らないのは、次をすべて 1 か所で守るため。

- パスは保管庫からの相対パスで受け取る。`..` などで保管庫の外に出るパスは拒む。
- 書き込みは一時ファイルに書いてから置き換える（次節）。
- 自分で書いた変更を、ファイル監視が「外部の変更」と取り違えないようにする。

コマンドの一覧（`src-tauri/src/vault/commands.rs`、`src-tauri/src/app_state.rs`）:

| コマンド | 動作 |
| --- | --- |
| `vault_open(path)` | 保管庫を開き、監視を始める。前の保管庫の監視は止める |
| `vault_list()` | `.md` とフォルダの一覧を返す（`.` で始まるものは除く）。未ダウンロードと衝突の疑いの印を付ける |
| `vault_default_dir()` | 保管庫を選ぶダイアログの最初の候補。iCloud Drive があればそこ、無ければホーム |
| `note_read(rel)` | 中身と、変更を見分けるためのハッシュ（blake3）を返す |
| `note_write(rel, content, base_hash)` | `base_hash` が今のファイルと合えば書く。合わなければ衝突（`currentHash` 付き）として返す |
| `note_create(rel)` / `note_rename(from, to)` | 作る / 名前を変える・移す。行き先のフォルダが無ければ作る。すでにあれば上書きせず失敗にする |
| `note_trash(rel)` | ゴミ箱に送る |
| `app_state_read()` / `app_state_write(json)` | アプリの状態（保管庫の外）を読む / 置き換えで書く |

- パスは `.md` で終わるものだけを受け付ける。`.` で始まる要素（隠しファイル）も拒む。
- シンボリックリンクで保管庫の外に出るパスは、実在する一番深い祖先を正規化して拒む。
- コマンドは `async` にしてあり、メインスレッド（ウィンドウ）を止めない。

外部の変更はイベント（`vault://changed`、`{ paths: string[] }`）で WebView に知らせる。
WebView は一覧を読み直し、開いているメモが含まれていれば読み直して比べる。

## 書き込み

- **置き換えで書く。** 同じフォルダに `.` で始まる一時ファイルを書き、`rename` で
  置き換える。途中で止まっても元のファイルは壊れない。一時ファイルは `.` で始まるので
  一覧には出ない。
- **書く前に確かめる。** 読んだときのハッシュ（`base_hash`）と今のファイルのハッシュが
  違えば書かずに衝突として返す。自動保存が他の端末の変更を黙って上書きしないため。
- **自動保存の時機。** 入力が止まってから約 500ms、別のメモに移るとき、ウィンドウから
  フォーカスが外れるとき。

## ファイルの監視

- macOS の FSEvents を `notify` クレートで受ける。150ms 続けて変更が無くなるまでまとめる。
- 自分で書いた直後の通知は、書いた内容のハッシュと今のファイルのハッシュが同じなら
  読み飛ばす。
- 開いているメモが外部で変わったとき:
  - 手元に未保存の変更が無ければ読み込み直す。カーソルとスクロールの位置はできるだけ保つ。
  - 未保存の変更があれば、エディタの上にその場で知らせを出し（トーストにはしない。
    消えては困るため）、「手元の版を残す」「外の版を読み込む」を選ばせる。

## iCloud 特有のこと

### 衝突ファイル

2 台で同時に書き換えると、iCloud は片方の版を `メモ 2.md` のような別名のファイルとして
残すことがある。また、衝突した版を `NSFileVersion` の「未解決の版」として持つこともある。

- MVP: 「`<名前> <数字>.md` があり、`<名前>.md` もある」ものを衝突の疑いとして一覧に
  印を付ける。2 つを見比べて片方を残す操作は後回しにする。
- 名前だけでは本当の衝突と偶然の名前を区別できない。`NSFileVersion` で正確に調べるか
  （Rust から `objc2` で呼ぶ）は、実際に衝突を起こして確かめてから決める。

### まだダウンロードされていないファイル

iCloud は容量を空けるために、ファイルの中身を端末から消して名前だけを残すことがある。

- macOS 14 以降（File Provider）では、中身の無いファイルも普通の名前で見え、読むと
  その場でダウンロードが始まる。読み込みが長く待たされうるので、`note_read` は
  待ち時間の上限を持ち、待っている間は「ダウンロード中」と出す。
- それより前の macOS では `.メモ.md.icloud` という隠しファイルとして見える。
  一覧では元の名前で「未ダウンロード」の印を付けて出し、開くときに `brctl download` で
  ダウンロードを頼み、15 秒まで待つ。待っている間はステータスバーに「ダウンロードしています」と出す。
- どちらの形になるかは実機で確かめる。

### ファイル名

- **Unicode の正規化。** macOS や iCloud から来るファイル名は、濁点が分かれた形（NFD）の
  ことがある。表示と検索では NFC にそろえ、ファイル操作には受け取ったままの名前を使う。
- **大文字と小文字。** APFS は既定で大文字と小文字を区別しない。`memo.md` を `Memo.md` に
  するような名前変更は、別の名前を 1 度挟んで 2 回に分ける。

## 規模

MVP では保管庫を開くときに全体を走査する。数千ファイルまでは問題にならない想定で、
それを超えて遅くなったら索引のキャッシュを検討する。
