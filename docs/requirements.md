# 要件定義

Treemo は、キーボードだけで書き終えられる macOS 向けの Markdown メモアプリ。
Vim で書け、メモの中にロジックツリーをキー操作だけで組み立てられる。

この文書は「何を作るか」を決める。「どう作るか」は [設計](architecture.md)、
実装の順番は [ロードマップ](roadmap.md) にある。

## 狙い

考えを整理するときは、文章とツリーを行き来する。既存の道具はどちらかに寄っている。

- Obsidian などの Markdown エディタは Vim で書けるが、ツリーは Mermaid を手で書くか
  プラグインに頼ることになり、組み立てながら考える速さが出ない。
- マインドマップやロジックツリーの道具はマウス前提で、データが独自形式に閉じる。

Treemo は、**文章の流れの中でツリーをキーボードだけで素早く組み立てられ、その結果が
ただの Markdown として手元に残る**ことを目指す。

## 対象

- まずは作者本人が毎日使う道具として作る。
- 将来は他の人にも配る独立したアプリにする。そのため、作者の環境を前提にした決め打ち
  （保管庫のパス、キー設定など）をコードに埋め込まない。
- 使う人は Vim の操作に慣れていることを前提にする。

## 決まっていること

壁打ちで決めた方針。変えるときはこの表を直してから実装する。

| 項目 | 決定 | 補足 |
| --- | --- | --- |
| 形態 | macOS 用のデスクトップアプリ（Tauri 2） | 他の OS は対象外 |
| 同期 | iCloud Drive 上のフォルダを保管庫として読み書きする。アプリ自身は同期を持たない | Obsidian と同じ考え方。詳細は [保管庫と iCloud](vault.md) |
| 保存形式 | 1 メモ = 1 つの `.md` ファイル | アプリ独自の情報はファイルに書かない |
| グラフの位置づけ | メモの中に ```` ```tree ```` のブロックとして埋め込む | 壁打ちの候補 A・B・C のうち C |
| グラフの種類 | MVP は左から右へ広がるロジックツリーだけ | 将来は他の配置や、ツリーではない辺も扱う |
| ノードの中身 | 複数行を書け、インラインの Markdown も使える | 記法は [ツリーブロック](tree-block.md) |
| 表示 | ライブプレビュー。カーソルのある行だけが生の Markdown で、それ以外は装飾して表示する | |
| アウトライナー機能 | 入れる | 見出しとリストの折りたたみ、チェックリスト、リスト項目の移動 |
| ツリーの編集画面 | メモの中（インライン）と全画面を切り替えられる | |
| マウス | 使える。ただし全操作がキーで完結し、UI はキー操作の手がかりを示す | [キー操作](keybindings.md) |
| リポジトリ | kazuvin.me とは分ける | lint などの設定と Kotoba デザインシステムを流用する |
| ライブプレビューの作り方 | 自作する。`@codemirror/lang-markdown` の構文木を読み、記号を隠す・装飾する Decoration を付ける | 既存の拡張は見出しを大きな文字で描くものが多く、Kotoba の 14px の上限と合わない。対象の記法も 8 つと少ない。実装は `features/editor/extensions/live-preview.ts` |

## 用語

| 用語 | 意味 |
| --- | --- |
| 保管庫（vault） | メモを置くフォルダ。アプリはこの中だけを読み書きする |
| メモ | 保管庫の中にある `.md` ファイル 1 つ |
| ツリーブロック | メモの中で ```` ```tree ```` と ```` ``` ```` で囲んだ範囲 |
| ノード | ツリーの 1 項目。ルート（親が無いもの）と部分木（あるノードとその子孫）も使う |
| モード | Vim の NORMAL / INSERT / VISUAL と、ツリーを操作する TREE |

## 機能要件

ID はロードマップと実装から参照するためのもの。

### 保管庫とファイル（VAULT）

- **F-VAULT-1** 初回起動で保管庫のフォルダを選ぶ。候補として iCloud Drive を最初に示す。
  最後に開いた保管庫を覚えておき、次回はそれを開く。
- **F-VAULT-2** 保管庫の中の `.md` をフォルダ階層のまま一覧にする。`.` で始まる
  ファイルとフォルダは出さない。
- **F-VAULT-3** クイックスイッチャー。ファイル名のあいまい検索で開く。一致するものが
  無ければ、入力した名前で新しく作れる。
- **F-VAULT-4** 新規作成・名前変更・移動・削除。削除したファイルは macOS のゴミ箱に入れる。
- **F-VAULT-5** 自動保存。保存ボタンは無い。入力が止まってしばらくしたとき、
  別のメモに切り替えたとき、ウィンドウからフォーカスが外れたときに書き込む。
- **F-VAULT-6** 外部の変更を反映する。開いているメモが別の端末などで書き換えられたら、
  手元に未保存の変更が無ければ読み込み直す。未保存の変更があれば衝突として知らせ、
  どちらを残すか選ばせる。
- **F-VAULT-7** iCloud が作る衝突ファイルと、まだ端末にダウンロードされていない
  ファイルを見分けて示す。

### エディタ（EDIT）

- **F-EDIT-1** CodeMirror 6 と Vim のキーバインドで編集する。モーション、テキスト
  オブジェクト、レジスタ、マクロ、`.` による繰り返しなど、Vim の基本が使える。
- **F-EDIT-2** ライブプレビュー。カーソルがある行（選択範囲にかかる行）だけを生の
  Markdown で表示し、それ以外の行は記号を隠して装飾する。対象は見出し、強調、
  インラインコード、リンク、リスト記号、チェックボックス、引用、水平線。
  見出しは Kotoba の制約（文字は 14px が上限）に従い、大きさではなく太さ・色・余白で
  段を付ける。
- **F-EDIT-3** アウトライナー機能。
  - 見出しとリスト項目を折りたためる。折りたたんだ状態はメモごとにアプリ側で覚え、
    ファイルには書かない。
  - チェックリストの項目をキーで切り替えられる。
  - リスト項目を、子の項目ごと字下げ・字上げし、上下に入れ替えられる。
- **F-EDIT-4** `:w`（保存）と `:e 名前`（メモを開く）の ex コマンドが使える。

### ツリーブロック（TREE）

- **F-TREE-1** ```` ```tree ```` のブロックを、左から右へ広がるツリーとして描く。
  記法は [ツリーブロック](tree-block.md) にある。
- **F-TREE-2** ブロックの表示には 4 つの状態がある。
  1. カーソルがブロックの外にあるときは、ツリーの絵として表示する。
  2. カーソルがブロックに乗ると、ブロック全体を選択状態にし、押せるキー
     （TREE モードに入る、ソースを表示する）を案内する。
  3. ソース表示にすると、ブロックを生のテキストに戻し、普通の Vim で編集できる。
     カーソルがブロックから出たら絵に戻る（F-EDIT-2 の「カーソル行だけ生で表示する」を
     ブロック単位に広げたもの）。
  4. TREE モードでは、ノードを選んでキーで組み立てる。
- **F-TREE-3** TREE モードでできること。ノード間の移動、兄弟ノードと子ノードの追加、
  中身の編集、部分木ごとの削除・コピー・貼り付け、兄弟間の入れ替え、字下げ・字上げ、
  折りたたみ、取り消しとやり直し。キーは [キー操作](keybindings.md) にある。
- **F-TREE-4** ノードの中身は、ノードの上に開く小さなエディタで書く。このエディタでも
  Vim が使え、複数行を書ける。
- **F-TREE-5** TREE モードの画面は、メモの中（インライン）と全画面をキーで切り替えられる。
  最後に使った方を覚えておく。
- **F-TREE-6** TREE モードでの変更はブロックのテキストに書き戻す。取り消しの履歴は
  メモ全体で 1 本にし、TREE モードの中でも外でも `u` で同じ順に戻れる。
- **F-TREE-7** キー 1 つで空のツリーブロックを差し込み、そのまま TREE モードに入れる。
- **F-TREE-8** ノードの中のインライン Markdown（強調、コード、リンク、取り消し線）を
  装飾して描く。
- **F-TREE-9** ブロックの中に記法として読めない行があっても描画を止めない。
  読めない行を示し、ソース表示で直すよう案内する。そうしたブロックでは TREE モードに
  入れない（書き戻しで行を失わないため）。

### 操作と手がかり（UX）

- **F-UX-1** すべての操作をコマンドとして登録する。コマンドパレットから名前で呼べ、
  パレットには割り当てたキーを並べて出す。
- **F-UX-2** which-key。リーダーキー（`<Space>`）を押すと、続けて押せるキーの一覧を出す。
- **F-UX-3** ヒント。キー 1 つで、画面の押せる要素（サイドバーの項目、ボタン、ノード）に
  1〜2 文字のラベルを付け、ラベルを打ってそこへ移る（Vimium や easymotion と同じ形）。
- **F-UX-4** 今のモードをステータスバーに常に出す。TREE モードの間は、操作中のブロックの
  枠でもそれとわかるようにする。
- **F-UX-5** TREE モードでは、次に押せる主なキーを薄く出す。ノードのすぐ近くに出すと
  隣のノードと重なるので、操作中のブロックの下端（全画面では上端）に 1 行で出す。
  設定で消せる。
- **F-UX-6** マウスで押せる要素には、ツールチップで割り当てたキーを出す。
- **F-UX-7** サイドバー、エディタ、パレットのあいだのフォーカスをキーで移せる。
  今どこにフォーカスがあるかを常に見せる。本文の端（サイドバーの側）で `h` / `l` を押しても
  サイドバーへ移れる。
- **F-UX-8** キー操作の一覧を画面で引ける。
- **F-UX-9** キーの割り当てを設定画面と設定ファイル（`keybindings.json`）で変えられる。
  変えた割り当ては、パレット・which-key・キー一覧・画面の案内にもそのまま出る。
- **F-UX-10** 設定画面（`⌘,`）で、サイドバーの位置（左右）、テーマ、TREE モードの案内、
  保管庫、キーの割り当てを変えられる。

## 非機能要件

| 観点 | 要件 |
| --- | --- |
| 速さ | 起動してから最後に開いていたメモを編集できるまで 1 秒以内。1 万行のメモでも入力の遅れを感じない。200 ノードのツリーで、TREE モードの 1 操作を 1 フレーム（16ms）以内に描き直す |
| データの安全 | 書き込みは一時ファイルに書いてから置き換え、途中で止まっても元のファイルを壊さない。アプリが勝手にメモの書式を変えない（詳細は [ツリーブロック](tree-block.md) の「書き戻し」）。削除はゴミ箱に送る |
| 持ち運べること | ツリーブロックは他のエディタや GitHub で開いても読める。折りたたみの状態などアプリだけが使う情報はファイルに書かない |
| 動作環境 | macOS 13 以降。Apple Silicon を優先する |
| アクセシビリティ | フォーカスリングを必ず見せる。色の使い方は Kotoba に従う |
| 配布 | MVP では自分の Mac でビルドして使う。署名と公証は他の人に配る段階で行う |

## MVP に入れないもの

- iOS / iPadOS 版、macOS 以外の OS
- ツリー以外の配置（フローチャート、放射状のマインドマップなど）
- ツリーではない辺（クロスリンク、合流）
- `[[wikilink]]` とバックリンク
- 全文検索（MVP ではファイル名で探すだけ）
- 画像の添付
- エクスポート（SVG / PNG / Mermaid）
- Vim を切る設定
- プラグイン、共有、共同編集
- 署名・公証、自動更新
- ダークモード（テーマを切り替える仕組みはあるが、Kotoba にダークテーマが無い）

## 決まっていないこと

実装の途中で決める。決めたらこの節から上の表へ移す。

- **保管庫の置き場所。** iCloud Drive の好きなフォルダにするか、アプリ専用の iCloud
  コンテナ（iOS の「ファイル」アプリからも見える）にするか。後者は署名が要る。
  iOS 版に手を付けるときに決める。MVP は前者。
- **衝突の見つけ方。** ファイル名から推測するか、macOS の `NSFileVersion` で正確に
  調べるか。[保管庫と iCloud](vault.md) を参照。
- **ツリーではない辺の記法。** [ツリーブロック](tree-block.md) で記号を予約してあるだけ。
- **ヒントのキー。** Vim の既存キーとぶつからない割り当てを [キー操作](keybindings.md) で
  仮決めしている。使ってみて見直す。
