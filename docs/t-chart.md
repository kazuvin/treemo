# T 字の図

メモに埋め込む T 字の図の記法と、DIAGRAM モードでの扱い。梅田悟司『「言葉にできる」は武器になる。』の
T 字型思考法を描くための図。要件は [要件定義](requirements.md) の TCHART にある。
ノードの書き方、書き戻す時機、検索、動きは [ツリーブロック](tree-block.md) と同じなので、ここには
違うところだけを書く。

## 考え方

最初に書き出した言葉を中心に置き、3 つの問いで考えを広げる。

| 問い | 向き | 働き |
| --- | --- | --- |
| なぜ？ | 下 | 考えを掘り下げる |
| それで？ | 右 | 考えを先へ進める |
| 本当に？ | 左 | 考えを戻して確かめる |

中心の言葉は、T の横棒と縦棒が交わるところに来る。答えの下には同じ問いを重ねられる
（なぜ？ の答えに、さらに なぜ？ と問う）。答えに別の問いを立てたいときは、その答えを中心にした
新しいブロックを作る。答えごとに 3 つの問いを付けられるようにすると、図が込み入り、`hjkl` の向きが
場所によって変わるため。

## 例

````markdown
```tchart
- 仕事がつまらない
  - なぜ？
    - 毎日同じ作業だから
      - 任される範囲が狭いから
    - 評価が見えないから
  - それで？
    - 新しい仕事に手を挙げたい
  - 本当に？
    - 先月の企画は楽しかった
```
````

中身はツリーブロックと同じ箇条書きなので、Treemo 以外で開いても問いと答えの組として読める。

## 記法

- 開始は行頭の ```` ```tchart ````。フェンスと info 文字列の決まりはツリーブロックと同じ
  （`~~~tchart` も受け付け、知らない設定は消さずに書き戻す）。`layout=` は使わない。
- ノードの書き方（`- `、字下げ、続き行、インライン Markdown）もツリーブロックと同じ。
- ルート（字下げの無いノード）が中心。1 つだけ書く。
- 中心の子が問い。中身は `なぜ？` `それで？` `本当に？` のどれか。`？` は半角の `?` でも、無くてもよい。
- 問いの子が答え。答えの子は、同じ問いを重ねた答えになる。

### そろえ方

読むときに、次のように T の形へそろえる。テキストを書き換えるのは DIAGRAM モードで変更したときだけ。

- 無い問いは、答えの無い問いとして足す。空のブロックは、中心が空の T として描く。
- 問いは なぜ？・それで？・本当に？ の順に並べる。
- 同じ問いが 2 度あれば、答えを 1 つにまとめる。

### 読めない行

ツリーブロックの読めない行に加えて、次の行も読めない行として扱う。読めない行があるブロックで
DIAGRAM モードに入れないのもツリーブロックと同じ。

- 2 つ目からのルートと、その配下の行
- 問いではない中心の子と、その配下の行

## 書き戻し

ツリーブロックの正規形に従う。そのうえで、問いは答えが無くても 3 つとも書き、なぜ？・それで？・本当に？
の順に、`？` を全角にして書く。

## レイアウト

- 中心の右に それで？、左に 本当に？ を、中心と縦の中央をそろえて置く。下には なぜ？ を、中心と横の
  中央をそろえて置く。中心と問いのあいだは 24px。
- 問いから先は、腕の向きのツリーとして組む。それで？ は左から右、本当に？ は右から左（左から右の配置を
  左右に裏返したもの）、なぜ？ は上から下。間隔はそれぞれの向きのツリーと同じ。
- 下の腕が横の腕と左右で重なるときは、下の腕を横の腕の下端から 48px あけたところまで下ろす（T の
  縦棒が伸びる）。横の腕は辺も含めた箱で避ける。ノードだけを避けると、問いから答えへの辺が下の腕の
  ノードを横切るため。
- 図の左右と下には 56px あけ、腕の先にノードを足す印が入るようにする。
- 中心は強い境界の枠と太めの文字で、問いはフロントマターのタグと同じチップの形で描く。
- 辺は親から子へ、その腕の向きで出入りする S 字の曲線。
- 現れるノードは、腕の親の側から滑り込む（本当に？ の腕では右から）。
- 実装は `features/diagram/utils/layout.ts` の `layoutTChart`。T の形へのそろえ方と、DIAGRAM モードの
  動きは `features/diagram/utils/t-chart.ts` にある。

## DIAGRAM モード

キーはツリーブロックと同じものを使う。違うのは次の点で、キーの一覧は [キー操作](keybindings.md) の
「T 字の図」にある。

- 入ると中心を選ぶ。
- 中心で `j` / `l` / `h` を押すと、なぜ？ / それで？ / 本当に？ へ移る。腕の中では、その腕のツリーの
  向きで動く。同じ深さのノードへ移るときは、同じ腕の中だけを渡る。
- 中心と問いは T の骨組みなので、消す・動かす・兄弟を足すことはできない。問いの中身も書き換えられない。
- 中心は中身だけを書ける。ノード編集の `Enter` と `Tab` は確定するだけで、兄弟も子も足さない。空で
  確定しても消さず、空の中心として残す。
- 問いでは、答えを足す（`Tab`）・答えとして貼り付ける（`]p`）・腕ごと折りたたむ（`za`）ことができる。
- 答えはツリーのノードと同じように扱える。ただし、問いのすぐ下の答えは字上げできない（問いの並びに
  出てしまうため）。
- `zM` ですべて折りたたんでも、中心は開いたままにする。
- 向きの切り替え（`gr`）は無い。押すとステータスバーで知らせる。
