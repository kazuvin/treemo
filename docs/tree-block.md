# ツリーブロック

メモに埋め込むロジックツリーの記法と、TREE モードの操作をテキストに書き戻す規則。
要件は [要件定義](requirements.md) の TREE にある。

## 例

````markdown
```tree
- 売上が落ちている
  - 客数が減った
    - 新規が減った
    - リピートが減った
  - 客単価が下がった
    - **値引き**が増えた
      セール期間が 2 週から 4 週に延びた
```
````

中身はただの Markdown の箇条書きなので、Treemo 以外で開いてもツリーとして読める。
これが、グラフを独自の形式ではなくテキストで持つ理由。

## 記法

### フェンス

- 開始は行頭の ```` ```tree ````。バッククォートは 3 つ以上で、`~~~tree` も受け付ける。
- 終了は CommonMark のコードブロックと同じで、開始と同じ種類の記号が同じ数以上並ぶ行。
- info 文字列（`tree` のあとに続く部分）は `key=value` を空白で区切った設定として読む。
  MVP で意味を持つ設定は無い。知らない設定も消さずに、そのまま書き戻す。
  - 将来の予定: `layout=lr`（左から右。既定）、`layout=tb`（上から下）、`layout=radial`（放射状）

### ノード

- `- ` で始まる行が 1 つのノードになる。`* ` と `+ ` も読む。
- 深さは字下げで決まる。直前のノードより深く字下げした項目は、その子になる。
  2 段以上深くても、直前のノードの子として読む。
- `- ` で始まらず、ノードの中身の開始列（`- ` の直後の列）以上に字下げした行は、
  そのノードの中身の続きになる。これで複数行のノードを書ける。
- 空行は読み飛ばす。ノードの中身に空行は含められない。
- 中身にはインライン Markdown（強調、コード、リンク、取り消し線）を書ける。
  見出し・コードブロックのようなブロック要素は書けない。
- ルート（字下げの無いノード）は 1 つでも複数でもよい。複数あれば上から順に並べて描く。

### 読めない行

次の行は「読めない行」として扱う。

- 最初のノードより前にある、空行ではない行
- `- ` で始まらず、どのノードの続きにもならない行（字下げが足りない）

読めない行があってもブロックは描く。そのうえで読めない行を目に見える形で示し、ソース表示で
直すよう案内する。読めない行を含むブロックでは TREE モードに入れない。書き戻しで行を
失わないため。

### 予約した記法

次の書き方はツリーではない辺のために取っておく。MVP ではただの文字として描く。

- 行末の `{#id}`（ノードに名前を付ける）
- 中身の `-> #id`（名前を付けたノードへの辺）

## データモデル

```ts
interface TreeBlock {
  /** 開始フェンスの記号と数（例: "```"） */
  fence: string
  /** info 文字列の tree より後ろ。読めなくても保持する */
  info: string
  roots: TreeNode[]
  /** 読めない行。1 つでもあれば TREE モードに入れない */
  strayLines: { line: number; text: string }[]
}

interface TreeNode {
  /** 開いている間だけ使う一時的な ID。ファイルには書かない */
  id: string
  /** 改行を含みうる。続き行の字下げは取り除いた形で持つ */
  content: string
  children: TreeNode[]
}
```

折りたたみの状態は `TreeNode` にもファイルにも持たせず、アプリ側に置く
（[設計](architecture.md) の「状態の置き場所」）。

## 書き戻し

### 正規形

TREE モードで書き戻すときは、ブロックの中身を次の形にそろえる。

- 記号は `- ` を使う。
- 字下げは 1 段あたりスペース 2 つ。
- 続き行は、そのノードの中身の開始列にそろえる。
- 行末に空白を残さない。
- 開始と終了のフェンス、info 文字列は元のまま残す。

### いつ書き換えるか

- TREE モードで 1 度でも変更したときだけ、そのブロックを正規形で書き直す。
  見ただけ、選んだだけのブロックには触らない。
- ブロックの外のテキストは一切変えない。

「アプリが勝手に書式を変えない」（要件定義の非機能要件）を守るのが目的。
`* ` で書いた箇条書きがいつのまにか `- ` になると、差分が読めなくなる。

### 往復の保証

テストで次の 2 つを保つ。

- どのツリー `T` でも `parse(serialize(T))` は `T` と同じ形になる。
- 正規形の文字列 `s` なら `serialize(parse(s))` は `s` に一致する。

## TREE モードの操作とテキストの変化

キーは [キー操作](keybindings.md) にある。どの操作も「ツリーを変える → ブロック全体を
正規形で書き直す」の 1 回の CodeMirror のトランザクションになり、`u` で 1 手ずつ戻れる。

| 操作 | ツリーの変化 |
| --- | --- |
| 下に兄弟ノードを追加 | 選んでいるノードの部分木の直後に、同じ深さの空ノードを差し込む |
| 上に兄弟ノードを追加 | 選んでいるノードの直前に、同じ深さの空ノードを差し込む |
| 子ノードを追加 | 選んでいるノードの最後の子として空ノードを足す（折りたたんでいれば開く） |
| 字下げ | 直前の兄弟の最後の子に移す。直前の兄弟が無ければ何もしない |
| 字上げ | 親の直後の兄弟に移す。ルートなら何もしない |
| 兄弟間の入れ替え | 隣の兄弟と部分木ごと入れ替える |
| 削除 | 部分木ごと取り除き、レジスタに入れる |
| コピー | 部分木を正規形のテキストにしてレジスタに入れる |
| 貼り付け | レジスタのテキストをツリーとして読み、兄弟または子として差し込む |

レジスタは Vim の無名レジスタと共通にする。TREE モードでコピーした部分木をテキストに
貼れば箇条書きになり、テキストでコピーした箇条書きを TREE モードで貼ればノードになる。

## レイアウト（左から右）

- 子は親の右に縦に並べ、親は子の塊の縦の中央に置く。
- 部分木どうしが重ならない範囲で詰める（Reingold–Tilford / Walker の tidy tree）。
- ノードの幅には上限（例: 32 文字ぶん）を設けて折り返す。高さは中身で決まる。
  そのため、レイアウトは実測したノードの大きさを入力に取る
  （描く → 大きさを測る → 位置を決める、の 2 段）。
- 辺は親の右端の中央から子の左端の中央へ、直角に折れる線で結ぶ。
- レイアウトは `(ツリー, ノードの大きさ) → 位置` の純粋な関数にする。
  将来 ELK.js などの別のエンジンに替えるときの境界はここに置く。
